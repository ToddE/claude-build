# inform9 Data Model and State Rules

## 1. How the pieces fit

- An **account** is one email address. It can hold businesses (Business Owner role) and a saved W-9 profile (Payee role).
- A **business** belongs to one account. A **payee** is a contact in one account, linked to one or more of its businesses.
- A **request** asks one payee for a W-9 for one or more businesses with one link. When the payee signs, the platform makes one **W-9 document** (a signed PDF) per business, and a **W-9 version** row links each document to its business and payee.
- A **share** is a W-9 a Payee sends on their own. It points to a W-9 document the Payee signed, not to any business.
- Taxpayer IDs and PDFs are encrypted before storage. `tin_last4` is stored in the clear so masked exports need no decryption.

## 2. Status rules

### Request (`requests.status`)

| From | To | Cause | Use case |
| --- | --- | --- | --- |
| (new) | sent | Owner sends the request | Request W-9 |
| sent | delivery_failed | Email bounces | Request W-9, Send W-9 Reminders |
| delivery_failed | sent | Owner resends, possibly after fixing the email | Follow Up on Incomplete Request |
| sent | sent | Owner resends (resend count up, reminder count reset) | Follow Up on Incomplete Request |
| sent or delivery_failed | completed | Payee signs or approves saved info | Complete and Sign W-9, Confirm and Reuse Saved Payee Information |
| sent or delivery_failed | declined | Payee declines (decline_code declined, not_right_person, or foreign_payee) | Payee Declines Request, Complete and Sign W-9 |
| sent or delivery_failed | canceled | Owner cancels, or archives the payee | Cancel Request, Edit or Archive Payee |

Completed, declined, and canceled are final. A new request is a new row. `reminders_ended = 1` on a sent request is the note "Reminders ended". An open request is `sent` or `delivery_failed`. `request_businesses.is_open` is 1 while the request is open, which enforces one open request per payee and business.

### What the owner's payee list shows

The portal shows one of five statuses per payee and business. Use the newest request for that payee and business.

| Newest request | Shown status | Extra |
| --- | --- | --- |
| none, or canceled | Not requested | |
| sent | Sent | "Reminders ended" note when `reminders_ended = 1` |
| delivery_failed | Delivery failed | |
| declined | Declined | Reason: the text, "Not the right person", or "Foreign payee" |
| completed | Completed | "Updated" marker when the newest W-9 version has `updated_marker = 1` |

A payee who has a completed W-9 and a new open request shows the open request's status, and the older W-9 stays downloadable.

### Share (`shares.status`)

| From | To | Cause | Use case |
| --- | --- | --- | --- |
| (new) | sent | Payee sends | Payee Sends W-9 to Business |
| sent | delivery_failed | Email bounces; link becomes inactive | Payee Sends W-9 to Business |
| sent | retrieved | First download | Business Recipient Retrieves Payee-Sent W-9 |
| sent or retrieved | misdirected | Recipient selects "I am not the right recipient"; link inactive | Business Recipient Retrieves Payee-Sent W-9 |
| sent or retrieved | not_accepted | Recipient opts out; link inactive | Opt Out of Payee-Sent W-9s |
| sent or retrieved | saved | Recipient saves to an account | Save Payee-Sent W-9 to Account |

"Expired" is not stored. A share shows as expired when `expires_at` has passed and the status is not saved. Whether to show this is an open issue in View Sent W-9s.

### Account (`accounts.status` and `send_status`)

- Status: pending, then active when the verification link is used, then canceled when the owner cancels.
- `send_status`: ok, paused (a flag was raised), blocked (an Administrator blocked sending). An Administrator moves a paused account to ok or blocked.

### Abuse flag

open, then reviewed with a decision of lift_pause, keep_pause, or block.

## 3. Rules the application enforces

- Every Business Owner query filters by `account_id`.
- Emails are lowercased before they are stored or compared.
- Link tokens, session tokens, and codes are stored as hashes. A plain token never reaches D1.
- Plan limits count active payees (not archived) and businesses, and read `plans` at each check.
- A resend is refused at `resend_count >= max_resends`.
- A payee-sent link is usable while `link_active = 1`, `expires_at` is in the future, and 24-hour downloads are under `daily_download_cap`. Both values are copied from settings when the share is sent, so later changes apply only to new shares.
- A reminder goes out only if the payee has no reminder in `email_log` for the same day, no row in `reminder_stops`, and no earlier bounce.

### Provider keys

SMTP2GO and Stripe keys (`smtp2go_api_key`, `stripe_secret_key`, `stripe_webhook_secret`, and later the Google client secret) go in the `secrets` table, encrypted with the platform key. The administrator screens show only the last four characters. A Worker secret with the same name takes precedence, so the first release can run without the screens. The master encryption key is always a Worker secret.

## 5. Email templates

Every email is one row in `email_templates`. All rows use one layout, `standard`, and each row switches on the parts it needs: a details table, a one-time code box, a button, extra links, a footnote, and an unsubscribe line. The layout and stylesheet live in `planning/email/`. The subject, heading, body, button text, and details hold placeholders such as `{{payee_name}}`, `{{business_name}}`, and `{{expires_text}}`. The renderer HTML-escapes every value and fails if a value is missing or a link is not https.

The first release loads the 22 rows from `email/dist/templates.seed.sql`, which `email/preview.mjs` generates from `email/messages.json`. Editing or adding messages in the administrator screens is a later addition. A new layout can be added later because `layout` is plain text. Each edit raises `version` and is written to the audit log.

## 6. Not stored in D1

- Signed PDFs: R2, encrypted, keyed by a UUIDv4.
- Current list filter or view: browser storage.
- SMTP2GO and Stripe keys outside the `secrets` table: Worker secrets.
