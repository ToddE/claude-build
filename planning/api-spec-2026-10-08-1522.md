# inform9 API Specification

## 1. Conventions

- Base path `/api/v1`. JSON over HTTPS. Request and response bodies use `snake_case`.
- IDs are UUIDs. Times are ISO 8601 UTC strings. Money is integer cents.
- Three kinds of caller:
  - **Session**: the `__Host-i9s` cookie set at sign-in. Used by `/me`, `/businesses`, `/payees`, `/requests`, `/payee/*`, `/billing`, `/exports`.
  - **Link**: a token in the URL path, with no cookie. Used by `/link/*`. A short-lived bearer token (sent in the `Authorization` header and held in page memory, never stored) covers the share retrieval steps after the one-time code.
  - **Admin**: a separate administrator session, with multi-factor. Used by `/admin/*`.
- Every state-changing request from a browser session also sends `X-Requested-With: inform9` and a matching `Origin`. Link requests carry their token and need no header.
- Lists use `?limit=` (default 50, maximum 200) and `?cursor=`. Responses return `{ "items": [...], "next_cursor": null }`.
- Creating requests, shares, and payments accepts an `Idempotency-Key` header. A repeat with the same key returns the first result.
- Taxpayer IDs go in on submit and never come back. Responses give `tin_type` and `tin_last4` only. The one exception is a full-ID export (section 9).
- A request owner sees only their own account's data. A missing or foreign id returns `404`.

### Errors

```json
{ "error": { "code": "validation_failed", "message": "Check the highlighted fields.", "fields": { "email": "Enter a valid email address." } } }
```

| HTTP | code | Meaning |
| --- | --- | --- |
| 400 | bad_request | Malformed body |
| 401 | unauthenticated | No valid session |
| 401 | invalid_credentials | Wrong email or password. One message for both |
| 402 | plan_limit | Plan limit reached. Body adds `limit`, `current`, `upgrade_path` |
| 403 | forbidden | Not allowed |
| 403 | password_required | A password confirmation is needed. Call `/auth/password/confirm` and retry |
| 403 | plan_required | The action needs a paid plan |
| 403 | sending_paused, sending_blocked | Payee-sent W-9s are paused or blocked for this account |
| 404 | not_found | No such record for this caller |
| 409 | conflict codes | `open_request_exists`, `email_registered`, `duplicate_business_name`, `duplicate_payee_email`, `resend_limit_reached` |
| 410 | link_unusable | Link is invalid, used, expired, canceled, or closed. One code, so the response does not say which |
| 422 | validation_failed | Field errors in `fields` |
| 423 | account_locked | Too many sign-in attempts. Body adds `locked_until` |
| 429 | rate_limited, cap_reached | Too many requests, or a daily send or download cap. Body adds `retry_after` |

### Rate limits (starting values, set in Cloudflare rules)

| Area | Limit |
| --- | --- |
| Sign-in and sign-up | 10 per minute per IP, plus the account lock |
| Password reset and verification emails | 5 per hour per email address |
| One-time code requests | 3 per 15 minutes per address and link |
| Link form submits | 20 per minute per IP |
| Everything else signed in | 120 per minute per session |

## 4. Payees

| Method and path | Request | Response | Use case |
| --- | --- | --- | --- |
| GET /payees | `?business_id=&filter=all\|open\|archived&status=&cursor=` | Items with `display_status` per business. See below | View and Download W-9s, Follow Up on Incomplete Request |
| POST /payees | `name, email, business_ids[]` | 201. 402 `plan_limit` (payees). 409 `duplicate_payee_email` with the existing payee | Add Payee Contact |

| POST /payees/{id}/restore | none | 200. 402 `plan_limit` | Edit or Archive Payee |

`display_status` follows the data model rules:

```json
{ "business_id": "...", "status": "sent", "note": "Reminders ended", "reason": null, "days_open": 12, "updated": false }
```

`status` is one of `not_requested, sent, delivery_failed, declined, completed`. `note` is only "Reminders ended". `reason` is the decline text, "Not the right person", or "Foreign payee".

## 5. Requests (Business Owner)

| Method and path | Request | Response | Use case |
| --- | --- | --- | --- |
| POST /requests | `payee_id, business_ids[], reminder_interval_days?, reminder_cap?` | 201 request. Sends the email. 409 `open_request_exists` with the existing request id. 403 `plan_required` for overrides | Request W-9 |
| GET /requests/{id} | none | request with `status_events` | Follow Up on Incomplete Request |

A request's expiry is `max(request.link_min_days, interval x cap + request.link_extra_days)`, set when the request is created or resent.

## 6. W-9s, downloads, and exports (Business Owner)

| Method and path | Request | Response | Use case |
| --- | --- | --- | --- |
| GET /w9-versions/{id}/download | none | `application/pdf` stream, decrypted. 403 `password_required` when the session has no recent confirmation | View and Download W-9s |
| POST /exports | `business_ids[] \| "all", format: qbo_csv\|xero_csv\|general_csv\|zip_pdf, tin_option: masked\|full, password?` | Streamed file. `zip_pdf` and `full` need `password` in the body every time. 403 if missing or wrong. 422 `nothing_to_export` | Export Payee Data |

The ZIP is streamed from R2 with each file decrypted in turn. A request over [MAX_EXPORT_FILES] files returns `422 too_many_files` with a suggestion to export by business.

## 7. Request link (Payee, no account)

All routes are under `/link/request/{token}` and need no cookie. An unusable link returns `410 link_unusable` on every route.

| Method and path | Request | Response | Use case |
| --- | --- | --- | --- |
| GET / | none | `{ businesses: [{name, address}], payee: {name, email}, has_account: bool }` | Complete and Sign W-9 |
| POST /submit | see below | 201 `{ completed_at, businesses[], completion_token, offer_account: true }` | Complete and Sign W-9 |
| POST /decline | `code: declined\|not_right_person\|foreign_payee, reason?` | 204 | Payee Declines Request |
| POST /stop-reminders | none | 204 | Send W-9 Reminders |
| GET /saved-info | session | `{ profile (masked), missing_fields[], businesses[] }`. 401 if not signed in as the payee's account | Confirm and Reuse Saved Payee Information |
| POST /approve | session. `edits?` | 201 completion, same shape as submit. 422 if fields are missing | Confirm and Reuse Saved Payee Information |
| POST /create-account | `completion_token, password, terms_accepted, marketing_opt_in` | 202 verification sent. 409 `email_registered` | Create Payee Account |

`has_account: true` tells the page to ask the payee to sign in first. The sign-in then uses `/auth/signin`, and the page calls `/saved-info` and `/approve`.

### POST /submit body

```json
{
  "legal_name": "Dana Whitfield",
  "business_name": null,
  "tax_classification": "individual",
  "llc_classification": null,
  "exempt_payee_code": null,
  "fatca_code": null,
  "address_line1": "12 Elm St",
  "address_line2": null,
  "city": "Richmond", "state": "VA", "postal_code": "23220",
  "tin_type": "ssn",
  "tin": "123-45-6789",
  "certify": true,
  "esign_consent": true,
  "signature_png": "data:image/png;base64,..."
}
```

The server checks the required fields, the TIN format, that `certify` and `esign_consent` are true, and that the signature image is a PNG under 200 KB. It then makes one signed PDF per business on the request, stamps each business as the requester, adds the receipt block (email, IP, user agent, UTC time), encrypts and stores each PDF, encrypts the TIN, writes one `w9_versions` row per business, completes the request, cancels reminders, and sends the notices. If storing fails, nothing is saved, the response is `503 storage_failed`, and the page keeps the entries on screen.

The `completion_token` is valid for 30 minutes and is used only by `/create-account`.

## 11. Webhooks (no session)

| Path | Source | Verification | Action |
| --- | --- | --- | --- |
| POST /webhooks/smtp2go | SMTP2GO | Shared secret in the URL or header, set in the administrator screens | Updates `email_log`. A hard bounce on a request or reminder sets Delivery failed and cancels reminders. A bounce on a share sets Delivery failed. A spam complaint adds the address to `reminder_stops` |
| POST /webhooks/stripe | Stripe | Stripe signature check with the webhook secret | Marks the payment, sets the plan and renewal date, sends the receipt |

Both are idempotent. A repeated event id changes nothing.

## 13. Scheduled jobs (not HTTP)

| Job | Interval | Work |
| --- | --- | --- |
| reminders | every 15 minutes | Find due reminders. Apply one per payee per day, no stops, no bounces. Combine same-day reminders from several businesses. Send. Update counts. Schedule the next. Mark Reminders ended at the cap |
| cleanup | hourly | Expire sessions, codes, completion tokens, and links past their expiry |
| retention | daily | Run data handling for canceled accounts past their date. Warn and archive inactive payee accounts |
| usage | daily | Refresh `account_usage` |

## 14. Gaps this spec surfaces

- Resolved: `requests.completion_token_hash` and `completion_token_expires_at`, and the `pending_saves` table, are now in the schema.
- Multi-factor enrolment is undecided, so those endpoints are placeholders.
- Google sign-in endpoints are not specified, since the feature is deferred.
- Sign-up returns `409 email_registered`, as the use case says, which lets someone check whether an address has an account. Turnstile and the rate limit reduce the risk. Returning a generic message with an email to the owner is the alternative.
- [MAX_EXPORT_FILES] is the setting `export.max_files`, default 500.
